# Правила VK Tools

Всё, что может меняться без программиста (параметры, категории, апдейтеры), лежит в CSV-файлах.

## Где лежат

| Уровень | Где | Кто меняет |
|---|---|---|
| Встроенные | `%AppData%\Autodesk\Revit\Addins\<год>\VKTools\config\` — ставятся с MSI | разработчик, в новой версии |
| Папка отдела | путь в VK Tools → Настройки | тот, у кого есть запись в папку |

Файл из папки отдела с тем же именем **заменяет встроенный целиком**. Файлов, которых нет в папке отдела,
берутся встроенные. Какой файл использован — в шапке отчёта (раздел «Правила»).

Если папка отдела недоступна (нет сети) или файл в ней с ошибками, VK Tools работает на встроенных правилах
и показывает это в отчёте. Начиная с Р1 изменяющие команды в таком состоянии не пишут в модель,
чтобы результат не разошёлся с коллегами.

## Формат

- Кодировка UTF-8 с BOM (Excel: «Сохранить как» → **CSV UTF-8 (разделитель — запятая)**; разделитель всё равно «;» по региональным настройкам).
  Файлы в ANSI (Windows-1251) тоже читаются.
- Разделитель — `;`. Строки, начинающиеся с `#`, — комментарии.
- Строка `#schema=1` обязательна: это версия формата. Файл с другой версией не загрузится, и в отчёте будет сказано почему.
- Первая строка без `#` — заголовки колонок. Порядок колонок не важен, лишние колонки игнорируются.
- Категории — системные имена Revit (`OST_PipeCurves`), а не русские названия: так правила работают и в английском Revit.

## Файлы

### parameters.csv — параметры для спецификаций ВК

| Колонка | Значения |
|---|---|
| Параметр | имя для отчёта |
| GUID | из ФОП отдела или ФОП SYS; по нему плагин ищет параметр |
| Обязательный | `да` — нет в проекте → «Ошибка»; `нет` → «Инфо» (нужен не во всех проектах, например LSR_) |
| Привязка | `Экземпляр`, `Тип` или `Любая` |
| Категории | через запятую; у параметра проекта каждая должна быть отмечена |
| Назначение | текст для отчёта |

### vk_categories.csv — категории спецификаций ВК

`Категория;Название`. По этим категориям ищутся пустые ADSK_Наименование и разные написания значений.

### updaters.csv — апдейтеры других надстроек

`Шаблон;Важность;Сообщение`. Шаблон — часть имени апдейтера или надстройки, регистр не важен.
Важность: `Ошибка`, `Предупреждение`, `Инфо`. Апдейтеры, которых нет в файле, попадают в отчёт одной общей строкой «Инфо».

### insulation_from_host.csv — что изоляция берёт от трубы

`Параметр;GUID`. Значения этих параметров у изоляции должны совпадать с трубой или фитингом, на котором она лежит.

### lookalike_values.csv — где искать двойники

`Параметр;GUID`. Для этих параметров ищутся разные написания одного значения: «B1» латиницей и «В1»,
«02 Этаж» и «02 этаж», лишние пробелы.

### nested_params.csv — что вложенные берут от родителя по умолчанию (Р2)

`Параметр;GUID`. Отмечено в окне «Перенос во вложенные», пока в модели нет своей настройки, и после «По умолчанию».
По умолчанию ADSK_Этаж, LSR_Имя системы, LSR_Тип системы. В окне можно отметить и другие общие параметры
и параметры проекта (см. «Настройки проекта» ниже).

### grouping.csv — таблица групп ADSK_Группирование по умолчанию (Р2)

`Группа;Название;Категория;Семейство;Действие`. Обязательны «Группа» и «Категория»; «Семейство» и «Действие» — с 0.5.0,
файлы 0.4.0 без них читаются как раньше.

| Колонка | Что писать |
|---|---|
| Группа | номер — любой текст: «4», «04», «4.1». Спецификация сортирует его как текст: «10» встанет перед «2», ставьте ведущий ноль |
| Название | для людей, плагин его не читает |
| Категория | имя BuiltInCategory (`OST_PipeAccessory`) или `*` — все остальные категории. Пусто — если строка про семейство |
| Семейство | маска имени семейства: `*` — любые символы, `?` — один, регистр не важен. Строка действует на само семейство и на всё, что в него вложено |
| Действие | пусто (писать) или «не трогать» — элементы строки плагин не пишет |

Порядок выбора правила: семейство верхнего родителя → своё семейство → категория → `*`. Среди строк семейств действует первая
подходящая. Без строки `*` элементы других категорий не трогаются. Служебные позиции (_SYS_…, заполненный SYS_Ключ) не трогаются.
По умолчанию: 0 спринклеры, 1 оборудование, 2 обобщённые модели, 3 сантехприборы, 4 арматура, 5 трубы и гибкие,
6 изоляция, 7 фитинги, 8 прочее.

Пример: кран поливочный нумеруется вручную, «Осевую линию» не трогать.

```
#schema=1
Группа;Название;Категория;Семейство;Действие
4;Арматура;OST_PipeAccessory;;
;Комплект вручную;;Кран поливочный*;не трогать
;Осевая линия;;Осевая линия;не трогать
8;Прочее;*;;
```

### kit_params.csv — параметры комплектов пожарных шкафов (Р2)

`Роль;Параметр`. Три роли: «Номер комплекта шкафа» (параметр типа шкафа, K), «Признак комплектующего»
(по наличию параметра вложенное считается комплектующим), «Ключ комплектующего» (K + ранг, например 3,01).
Ищутся по имени: в проектах разных лет семейства шкафов свои. Шкаф получает «группа.000000003.00», комплектующие — «группа.000000003.01» и т. д.

### schedule_form.csv — графы спецификации «Создать спецификацию» (Р6)

`Заголовок;Параметр;GUID;Ширина, мм;Итог;Скрыть;Сортировка;Выравнивание`. По умолчанию — ГОСТ 21.110-2013, форма 1 (сумма видимых граф 395 мм,
лист А3). Параметр ищется по GUID; нет в проекте — графа пропускается с замечанием. `Итог=да` — суммировать в неразвёрнутой строке (количество),
`Скрыть=да` — графа только для сортировки (ADSK_Группирование), `Сортировка` — 1, 2, 3… после заголовков по системам и этажам,
`Выравнивание=центр` — по центру. Действует только для встроенной формы: у копии эталона оформление эталона.

### schedule_groups.csv — группы систем для быстрого выбора (Р6)

`Группа;Начинается с;В названии`. «Водоснабжение;В, Т;систем водоснабжения» даёт кнопку «Системы: водоснабжение» и имя
«Спецификация систем водоснабжения». Начала имён — через запятую, без учёта регистра. Группа хранится в созданной спецификации:
«Обновить» добавит в неё новые системы с тем же началом.

### VK_Сокращение системы — свой параметр VK Tools (с 0.13.0)

Не из ФОП отдела. Плагин пишет свой ФОП в `%LocalAppData%\VKTools\fop\VK_ФОП.txt` (одна строка, GUID `788b1069-9783-4da0-bfc6-cf6885948e7c`),
на время чтения подставляет его Revit и сразу возвращает путь к ФОП отдела. Параметр добавляется в проект (экземпляр, текст, группа «Данные»)
при «Системе и этаже» или «Создать спецификацию», если его нет или он не у всех категорий ВК. GUID не менять: по нему параметр ищется во всех проектах.

### calc_resources.csv, calc_pipe_rules.csv, calc_supports.csv — расчётные позиции (Р3)

Таблицы по умолчанию для «Расчётных позиций» — те же, что `resources.csv`, `pipe_rules.csv`, `supports.csv` Dynamo-набора
spec_calc_items v0.4.1 (файлы набора импортируются в окне без правки).

- **calc_resources.csv** — `Код;Наименование;Ед_изм;База;Расход;Слоёв;Запас;Порядок;Округление;Основание[;параметры…]`.
  Ресурс = типоразмер служебного семейства. База: `m2` (площадь труб π·Dнар·L), `m` (длина), `pcs` (число креплений),
  `sup_kg` (масса креплений). Количество = база × Расход × Слоёв × Запас, вверх до шага «Округление».
  Группа позиции — «9.N», N — номер ресурса по «Порядку». Колонки после «Основание» — имена параметров позиции
  (например `ADSK_Завод-изготовитель`): значение пишется в тип, пустое — не пишется.
- **calc_pipe_rules.csv** — `Сегмент;Наименование;DN_от;DN_до;Изоляция;Шаг_гор_м;Шаг_верт_м;Ресурсы;Примечание`.
  Первая подходящая строка сверху; маски с `*`; Изоляция `да` / `нет` / пусто; Ресурсы — коды через «,»
  (пусто — трубе ничего не нужно: оцинковка не красится). Шаг_гор_м / Шаг_верт_м в правиле с `sup_kg` заменяют шаг
  таблицы креплений (пластик, по рекомендациям изготовителя); масса — из таблицы, для DN не из ряда — ближайшая строка.
- **calc_supports.csv** — `DN;Шаг_изол_м;Шаг_неизол_м;Масса_изол_кг;Масса_неизол_кг;Примечание`
  (СП 73.13330.2016, п. 6.1.8, табл. 2; массы — калькулятор slpl.ru/node/218).
- **calc_cord.csv** (с 0.8.0) — `DN_от;DN_до;Ресурс;Примечание`: какой шнур (ресурс с базой `cord`) идёт в гильзы трубы
  этого DN. База `cord` — метры шнура в один слой: π·(Dнар + добавка)·Lгильз / шаг витка / 1000 по гильзам на трубах системы;
  с 0.9.6 — только гильзы в наружных (подпорных) стенах и фундаментах модели и связей (флажок на вкладке, ключ `calc.sleeveAll`); дальше × Расход (1: «Расчет гильз и шнура.xlsx» без ×4, решение ведущего 2026-10-29) × Слоёв × Запас. DN40 — Ф12 мягкий.
- **calc_reserve.csv** (с 0.9.0) — `Семейство;Тип;Запас_%;Округление;Примечание`: запас на штучные позиции по строке
  спецификации, итог = ⌈N × (1 + Запас_%/100)⌉ до шага «Округление». Семейство и Тип — имя или маска, пустой Тип — все,
  первая подходящая строка. По умолчанию — хомуты Rapid, Kralle, CV (Grip E W2) и муфты грувлок («Влж_Муфта грувлочная»), 20 %, целые штуки.

## Настройки проекта (с 0.5.0)

Выбор параметров переноса, таблица групп и комплекты (с 0.6.0) хранятся в самой модели (Extensible Storage, не в параметрах и не в ФОП):

- пока в модели своей настройки нет, работают файлы выше (папка отдела или встроенные);
- «Сохранить» в окне модуля или «Применить» с изменённой настройкой записывают её в модель (в журнале отмены —
  «VK Tools: настройки проекта» или вместе с записью значений);
- «По умолчанию» подставляет правила из файлов, а «Сохранить» после него удаляет настройку из модели;
- в совместной модели настройка — обычный элемент: после сохранения синхронизируйте модель, тогда коллеги увидят её;
  пока она занята другим, сохранить нельзя (плагин скажет кем);
- перенести таблицу групп в другой проект: «Экспорт…» в одном, «Импорт…» в другом. Экспорт — файл в формате grouping.csv,
  его можно положить и в папку правил отдела, тогда он станет умолчанием для всех проектов без своей таблицы.

### Комплекты проекта (с 0.6.0)

Вкладка «Комплекты» окна «Группирование». Хранятся в модели вместе с таблицей групп, «По умолчанию» их не сбрасывает.
Перенос в другую модель — «Экспорт…» и «Импорт…» на вкладке (импорт заменяет комплекты в окне целиком).

Файл экспорта (и значение в модели) — CSV UTF-8 c `#schema=1`, две разновидности строк:

| Строка | Семейство | Тип | Вложенное семейство | Вложенный тип | K |
|---|---|---|---|---|---|
| состав | родитель | пусто — все типоразмеры, иначе свой состав этого типоразмера | вложенное | пусто — любой типоразмер | пусто |
| номер | родитель | типоразмер | пусто | пусто | целое 1…999999 |

Порядок строк состава — ранги .01, .02… Родитель всегда .00. K у разных типоразмеров разные; их присваивает плагин,
руками править не нужно. Пример:

```
#schema=1
Семейство;Тип;Вложенное семейство;Вложенный тип;K
469_Кран поливочный_ПЛК;;Кран шаровой муфтовый;;
469_Кран поливочный_ПЛК;;Рукав резинотканевый;;
469_Кран поливочный_ПЛК;;Штуцер с резьбой и накидной гайкой;;
469_Кран поливочный_ПЛК;d25;;;1
```

ADSK_Группирование комплекта: «группа.K.ранг», группа — из таблицы групп для родителя, K и ранг как у шкафов ПК
(`4.000000001.00`, `4.000000001.01`…). Вложенные, которых нет в составе, получают группу по таблице.

### Расчётные позиции (с 0.7.0)

Окно «Расчётные позиции» хранит в модели (ключи `calc.*`, только то, что отличается от умолчания): отмеченные
спецификации, параметр системы (по умолчанию `LSR_Имя системы`), номер группы (по умолчанию `9`), таблицы
выше настройки гильз (семейство-маска, параметр длины, добавка к Dнар и шаг витка, по умолчанию 10 и 10 мм) и таблица запаса на штучные. Перенос в другой проект — «Экспорт…» / «Импорт…» на вкладке таблицы; отметки спецификаций и параметр системы
задаются в каждом проекте заново.

## Как править

1. Скопируйте нужный файл из встроенных в папку отдела.
2. Откройте в Excel, поправьте, сохраните как CSV UTF-8.
3. VK Tools → Настройки → «Проверить»: зелёным — файл подхватился, красным — что не так.
4. Запустите «Проверить модель» и посмотрите раздел «Правила» в шапке отчёта.
