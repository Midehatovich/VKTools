# VK Tools — итог Discovery

2026-10-07, требования подтверждены 2026-10-08. Сводка по REQUIREMENTS.md, QUESTIONS.md, DISCOVERY-LOG.md, GOLDEN-CASES.md. 

## 1. Что это

Надстройка Revit на C# для отдела ВК (8 человек, Revit Server). Она заменяет Dynamo-скрипты проекта одной вкладкой «VK Tools». Каждая команда сначала показывает, что изменится, и пишет в модель только после «Применить». Правила (нормы, таблицы, форматы) лежат вне кода, и отдел правит их без программиста.

## 2. Что входит (все 7 модулей нужны в каждом проекте, SYS — в проектах LSR)

| Модуль | Что делает | Пишет в модель | Эталон логики |
|---|---|---|---|
| MEP | Объединяет «В1 1», «В1 2» в «В1» | состав систем | PipingSystemMerge v1.2 |
| NEST | Родитель → Shared-вложенные: ADSK_Этаж, LSR_Имя системы, LSR_Тип системы | да | NestedParamSync v2.1 (полный прогон подтверждён) |
| GRP | ADSK_Группирование 0…9, затем ключи комплектов ШПК | да | adsk_grouping + fire_cabinet_postprocess |
| CALC | Расчётные позиции по системам: грунтовка, эмаль, крепления (кг), бентонитовый шнур (м), запас 20 % на соединительные хомуты с округлением вверх по строке; новые позиции и коэффициенты — строкой в конфигурации | да, служебное семейство | spec_calc_items v0.3 + калькулятор ведущего + Excel шнура + ТЗ ведущего по хомутам |
| INS | Изоляция берёт от трубы ADSK_Этаж, LSR_Имя системы и Dнар; имя «…толщиной 25 мм для трубы D = 33,5 мм» пишет по включённой в проекте настройке | да | NestedParamSync v2.1 (шаги 1б, 2), InsulationPipeOD v1.0.2 |
| SYS | LSR_Имя системы из сокращения, ADSK_Этаж из уровня | да | NestedParamSync v2.1, шаги 1 и 1б |
| PIPE | Проверка ADSK_Наименование труб | только проверка (имена пишет BIM2B) | правила из треда по трубам |
| VAL | «Проверить модель» перед выпуском: пустые и расходящиеся значения, параметры спецификаций у категорий | нет | — |

## 3. Что не входит
- Соединение труб, правка геометрии, правка семейств и их lookup-таблиц.
- Автозапуск при изменении модели (IUpdater). Только ручной запуск.
- Запись имён труб, пока в моделях работает BIM2B (включается в настройках проекта, когда BIM2B уберут). Имена изоляции плагин пишет, как твой скрипт, если это включено в проекте.
- Revit 2019–2020. Сбор коллизий Navisworks.

## 4. Порядок релизов

```
Р0  Каркас + «Проверить модель»      вкладка, Preview/Report, лог, правила, установщик
Р1  MEP   объединение систем          ← твой приоритет №1
Р2  NEST + GRP                         вложенные, группирование, комплекты ШПК
Р3  CALC                               окраска, крепления, шнур
Р4  INS + SYS                          изоляция, система/этаж
Р5  PIPE                               проверка имён труб
```
Каждый релиз: ставишь, гоняешь на копии модели параллельно со своим Dynamo, сравниваешь отчёты, принимаешь, граф уходит в архив. Revit 2021, 2022, 2024.

## 5. Как плагин защищает модель

```
Команда
  │
  ▼
Pre-check ── параметры найдены по GUID? конфигурация читается? апдейтеры BIM2B есть?
  │           нет → запись запрещена, причина в отчёте
  ▼
Сбор (только чтение)
  ▼
План изменений ── правило не найдено / данных нет → значение НЕ трогаем, строка в отчёте
  ▼
Preview ── таблица «было → станет», фильтры, галочки по группам. Закрыл окно — ничего не изменилось
  ▼  «Применить»
Запись ── одна строка в истории отмены (Ctrl+Z откатывает весь запуск)
          пишем только изменившееся; занятое коллегой, ReadOnly, связи — пропуск с причиной
  ▼
Контроль ── повторный план = 0 изменений, иначе «перезаписано после записи» (например, BIM2B)
  ▼
Отчёт + лог ── клик по строке выделяет элемент в Revit; экспорт в CSV для Excel
```

## 6. Предварительная архитектура (уточню после твоего «да»)

```
VKTools.Core       чистая логика без Revit: правила, формулы CALC, разбор имён систем,
                   форматы, план изменений. Покрыта автотестами на GitHub
VKTools.Revit      адаптер к Revit API: сбор элементов, параметры по GUID, worksharing,
                   транзакции. Отдельная DLL под каждую версию Revit
VKTools.UI         WPF: вкладка, Preview, Report, настройки
VKTools.Installer  установка в профиль пользователя без прав администратора
```

Правила — три уровня:
```
встроенные (в установке)  →  папка отдела (путь в настройках)  →  настройки проекта (в модели)
                             перекрывает встроенные               какие модули включены,
                                                                  режим «только проверка»
```
Таблицы (нормы ЛКМ, шаги и массы креплений, правила труб, типы → правила) — CSV, их можно открыть в Excel, как сейчас resources.csv. Структура и настройки — JSON. В шапке отчёта — версия правил.

Технические решения, принятые без тебя: DISCOVERY-LOG §6 (D-001…D-006).

## 7. Подводные камни внедрения

| Что может пойти не так | Что делаем |
|---|---|
| BIM2B у коллег перепишет то, что записал плагин | Имена труб не пишем; запись имён изоляции включается в проекте явно, с предупреждением об апдейтере BIM2B; контроль после записи ловит перезапись |
| Excel сохраняет CSV в ANSI, и кириллица в правилах ломается (как было с хомутами) | Плагин читает UTF-8, UTF-16 и ANSI, а битые символы останавливает проверкой правил |
| У 8 человек разные версии правил | Версия правил в шапке отчёта; общая папка, как только появится путь |
| Revit спрашивает «Загружать всегда?» для неподписанной надстройки | Инструкция в INSTALL.md; подпись — если потребует ИТ |
| Чужие надстройки грузят свои версии тех же DLL | Сторонних библиотек в установке почти нет, каждая с проверкой лицензии и фиксированной версией |
| Элементы заняты коллегами на Revit Server | Не пишем, в отчёте видно, кто держит; повторный запуск после синхронизации |
| Настройки проекта в модели хранятся на «Сведениях о проекте» | Изменить их можно, только если этот элемент никто не занял; плагин скажет, кто занял |
| Объединение систем через API на модели ещё не проверено | MEP выходит первым, только с Preview и галочками; проверка на копии |
| Revit нет в облаке, где я пишу код | Логика проверяется автотестами; в Revit — командой «Самопроверка» на тестовой модели у тебя |

Полный реестр рисков — DISCOVERY-LOG §8.
