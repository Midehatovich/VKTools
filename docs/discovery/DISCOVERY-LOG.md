## 2. Карта функций

```
Источник истины в модели              Модуль   Что пишет                       Что сейчас делает это
────────────────────────────────────  ──────   ─────────────────────────────   ─────────────────────────────────────
PipingSystem «В1 N»                 → MEP     состав систем                   PipingSystemMerge v1.2 (не проверен)
Родитель → Shared-вложенные         → NEST    ADSK_Этаж, LSR_* у вложенных     NestedParamSync v2.1 шаг 3 (проверен)
Шкаф ШПК → комплектующие            → GRP     ключ комплекта (K + ранг)        fire_cabinet_postprocess v1.0 (получен)
Категория элемента                  → GRP     ADSK_Группирование 0…9           adsk_grouping_2022.py
Трубы спецификации + нормы/формулы  → CALC    _SYS_SpecCalcItem, SYS_*         spec_calc_items v0.3 + resources.csv
Код правила (по имени типа) + сегм. → PIPE    ADSK_Наименование труб          сейчас пишет BIM2B Updater
Основа изоляции (HostElementId)     → INS     ADSK_Этаж, LSR_Имя системы      NestedParamSync v2.1 шаги 1б и 2 (проверен)
Тип изоляции + толщина + Dнар трубы → INS     U_Наружный диаметр, ADSK_Наим.  InsulationPipeOD v1.0.2 (запись проверена)
Сокращение системы, уровень         → SYS     LSR_Имя системы, ADSK_Этаж       NestedParamSync v2.1 шаги 1 и 1б (проверен)
Lookup-таблицы хомутов              → FAM     ничего (только проверка)        ручная правка CSV
Всё выше                            → VAL     ничего (только проверка)        контрольные спецификации вручную
```

Цепочка «Полное обновление» (порядок важен: каждый шаг читает результат предыдущего):

```
Pre-check: параметры есть (по GUID)? апдейтеры BIM2B? занятые элементы? конфигурация читается?
  ↓
MEP   объединение систем (только по явному выбору групп, в полное обновление не входит по умолчанию)
  ↓
SYS   LSR_Имя системы, ADSK_Этаж          (только проекты LSR)
  ↓
PIPE  ADSK_Наименование труб               (только проверка, пока в проекте работает BIM2B)
  ↓
INS   параметры изоляции от основы
  ↓
NEST  родитель → вложенные
  ↓
GRP   ADSK_Группирование, затем ключи комплектов ШПК (ключ строится от группы)
  ↓
CALC  расчётные позиции
  ↓
Post-validation (повторный Preview = 0 изменений) → Report
```

Почему порядок релизов (§7) отличается от порядка выполнения: модули пишут разные параметры, и каждый можно выпустить отдельно; цепочка собирается, когда готовы все.

## 3. Находки раунда 1 (кратко)

1. BIM2B пишет ADSK_Наименование труб и держит в модели «Bim2b Dynamic Pipe Insulation Updater» → риск «A → B → A». Решено: плагин пишет имена труб только когда BIM2B для этого отключён (REQ-PIPE-005).
2. В работе Revit 2021 и 2022 → нужна сборка под несколько версий. Решено: 2021–2026 (§5).
3. spec_calc ищет окрашиваемые трубы по словам в наименовании → при смене формата имён окраска ломается. Решение: CALC берёт трубы по коду правила (REQ-PIPE-008).
4. Все скрипты устроены как «пробный прогон → запись одной транзакцией → контрольный прогон». Это и есть Preview → Apply.
5. На реальной модели проверен только nested_param_sync (v2.0 пробным прогоном, v2.1 — полным 2026-10-07).

## 4. Находки раунда 2 (по файлам)

1. **Рабочие графы = скрипты проекта.** Python в .dyn с твоего ПК побайтно совпадает с knowledge/scripts. Значит, эталон логики для плагина — эти файлы, других версий нет. Dynamo 2.12.1.
2. **Постобработка ШПК получена** (fire_cabinet_postprocess_v1.0.py): ключ = «группа.ключ» шириной 12 знаков, верхний родитель ищется через SuperComponent до 10 уровней.
3. **Параметр комплекта не из ФОП отдела.** Скрипт пишет `ADSK_Позиция_Комплект`, а в ФОП есть только `ADSK_ПозицияКомплект` (число). Q-205.
4. **В ФОП нет параметра «код правила».** Есть LSR_Код типа / элемента / по классификатору без описания. Использовать чужие по смыслу параметры не буду (D-002).
5. **Служебное семейство сохранено в Revit 2022** → в проекты 2021 оно не загрузится (C-012). D-005.
6. **Запас ЛКМ:** рабочий resources.csv (01.10) — 1,1; копия в проекте — 1. Q-207.
7. **Пути к CSV в графе расчётных позиций ведут в несуществующую папку** «Скрипты Revit\2022\». Если граф сейчас запускается, значит, пути у тебя другие; для параллельного прогона на приёмке их надо будет выбрать заново в узлах File Path.
8. **Граф переноса параметров сохранён с IN[2]=True (запись) и IN[5]=True (этаж из уровня).** Если у тебя Dynamo в режиме «Автоматически», граф пишет в модель сразу при открытии, без пробного прогона. Держи режим «Вручную».
9. **Нашёл `Собрать коллизии.bat`** (Navisworks → XLSX). К ВК-плагину не относится, в backlog.
10. **NestedParamSync v2.1 проверен полным прогоном в Revit** (тред «Перенос параметров…», 2026-10-07). Это эталон для NEST, SYS (включая ADSK_Этаж из уровня) и параметров изоляции от основы. Файл называется `nested_param_sync_v1_2022.py`, но внутри v2.1.
11. **BIM2B собирает и имя изоляции** («Комментарии к типоразмеру» + толщина + U_Наружный диаметр), а не только труб. Тред по изоляции сознательно не стал писать свой скрипт для имени. Плагин делает так же: имена изоляции и труб только проверяет, пока в проекте работает BIM2B.
12. **Шаги креплений из калькулятора ведущего = СП 73.13330.2016, п. 6.1.8, табл. 2** (сверил строки 15, 50, 150 по цитате на normacs.info). Массы одного крепления источника не имеют — это данные ведущего. Калькулятор знает DN 70, а не 65, и только сталь.
13. **Формула шнура в Excel не использует свои же колонки** «Толщина шнура» и «Кол-во слоёв»: везде подставлены 10 мм и множитель 4. Вопрос Q-301.
14. **Запас 1,1 = «+10 % на фасонку»** из замечаний ведущего. Это не запас на потери, а учёт окраски фасонных частей, которые плагин не считает отдельно.
15. **ADSK_Позиция_Комплект живёт в семействе начинки шкафа**, а не в ФОП. В проекте 2021 у шкафов свои семейства (Сортировка_Позиция вместо Сортировка_Целое), но комплекты там тоже собраны.
16. **Имя изоляции теперь пишет скрипт, а не BIM2B.** InsulationPipeOD v1.0.2 проверен в Revit с записью (2026-10-07): BIM2B Updater падал с NullReferenceException. Плагин повторяет поведение скрипта, запись имени включается в проекте.
17. **ТЗ ведущего: запас 20 % на соединительные хомуты** с округлением вверх по строке спецификации (⌈N × 1,2⌉). Штатно не решается; CALC должен уметь свой коэффициент запаса и округление вверх на каждую позицию. Механизм прорабатывается в треде по хомутам.

## 6. Технические решения (мои, предварительные)

| ID | Решение | Почему |
|---|---|---|
| D-001 | Выпуск 2021/2022/2024, сборка 2021–2026, см. §5 | отдел работает в 2021, 2022, 2024; переход на новые версии без переделки |
