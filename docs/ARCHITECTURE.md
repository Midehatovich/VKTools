# Архитектура VK Tools

## 1. Сборки

```
VKTools.Core.dll      чистая логика без Revit API: правила CSV, кодировки, отчёт, лог, настройки,
                      сравнение значений. net48 + net8.0. Покрыта автотестами (tests/VKTools.Core.Tests)
VKTools.dll           надстройка Revit (src/VKTools.Revit): вкладка, команды, проверки модели,
                      окна WPF. Отдельная сборка под каждый год Revit
config\*.csv          встроенные правила, лежат рядом с DLL
VKTools.addin         манифест; лежит в папке Addins\<год>, DLL — в подпапке VKTools\
```

Почему UI не вынесен в отдельную сборку (в предварительной архитектуре был VKTools.UI): окна вызывают
Revit API (ExternalEvent, Document), значит, UI всё равно пришлось бы собирать под каждый год Revit.
Две сборки на год вместо одной — больше файлов в установке и больше шансов на рассинхрон версий.
UI лежит в папке `src/VKTools.Revit/UI` и от логики отделён границей «Core ↔ Revit».

## 2. Поток «Проверить модель»

```
CheckModelCommand  [Transaction(ReadOnly)] — Revit не даст открыть транзакцию
   │
   ▼
ModelCheckRunner
   ├─ ConfigLoader: для каждого правила — файл отдела или встроенный, проверка схемы и колонок
   │     ошибки правил → строки «Правила VK Tools» в отчёте
   ├─ RuleTables.Parse*: строки CSV → типизированные правила (GUID, категории, важность)
   ├─ категории ВК: имя BuiltInCategory → категория этого Revit (неизвестная → строка в отчёте)
   └─ проверки IModelCheck, каждая в try/catch (упавшая проверка не прячет остальные):
         ParameterBindingCheck   параметры по GUID, общий ли, экземпляр/тип, категории привязки
         UpdaterCheck            UpdaterRegistry.GetRegisteredUpdaterInfos(doc)
         EmptyNameCheck          ADSK_Наименование у экземпляра и типа; строка на типоразмер
         InsulationHostCheck     PipeInsulation.HostElementId → сравнение параметров
         LookalikeValuesCheck    ValueNormalizer: ключ сравнения, группы двойников
   ▼
CheckReport (Core) ──► ReportWindow (немодальное, одно на сессию)
                          «Показать в модели» → ExternalEvent → SelectElementsHandler
                          «Сохранить CSV» → CheckReport.ToCsv() → UTF-8 с BOM
```

Одна проверка выводит не больше 5000 строк и итоговую строку «показаны первые N из M»: окно
отчёта должно открываться и на большой модели.

## 3. Правила

```
встроенные (config\ рядом с DLL)  ──►  папка отдела (путь в настройках)
                                        файл с тем же именем заменяет встроенный целиком
```

- Целиком, а не построчно: по шапке отчёта всегда видно, по какому файлу посчитан результат.
- Папка отдела недоступна (нет сети, VPN) — ждём не дольше 3 секунд, работаем на встроенных,
  `WriteBlocked = true`. Проверки работают, будущие изменяющие команды откажутся писать (REQ-CFG-003).
- Файл отдела с ошибками — то же самое: встроенные правила, запись запрещена, ошибки в отчёте.
- Битые встроенные правила — проверки, которые от них зависят, пропускаются со строкой «Ошибка».

Формат файлов — [CONFIGURATION.md](CONFIGURATION.md).

## 4. Различия версий Revit

Все различия API собраны в `src/VKTools.Revit/Compat/RevitCompat.cs` и закрыты константами
`REVIT2024_OR_GREATER` и т. п. из csproj:

| Что | Где меняется |
|---|---|
| `ElementId.IntegerValue` → `ElementId.Value` (long) | 2024 добавлен `Value`, 2026 удалён `IntegerValue` |
| `Category.BuiltInCategory` | появился в 2023; раньше — отрицательный `Id` |
| .NET Framework 4.8 → .NET 8 | 2025 |

Остальной код вызывает `id.ToLong()`, `value.ToElementId()`, `category.ToBuiltInCategory()`.
В отчёте и логе ElementId — `long`.

## 5. Безопасность модели

| Правило | Как обеспечено в Р0 |
|---|---|
| Проверка ничего не пишет | Все команды Р0 — `TransactionMode.ReadOnly` |
| Нет автозапуска | Нет IUpdater, нет подписки на события документа |
| Нет данных — нет записи | Проверки не предлагают «правильное» значение, если его неоткуда взять: у двойников «Ожидается» пусто |
| Сбой не роняет Revit | Каждая команда и проверка в try/catch, ошибка в лог и в отчёт |

С Р1 добавлена первая изменяющая команда — «Объединить системы» (§9): Preview → пробный прогон → Apply.

|---|---|

## 7. Окна без XAML

Окна WPF собраны в коде (`new Window`, `new DataGrid`), без XAML-компиляции. Так оба проекта
собираются любым .NET SDK, в том числе в Linux-контейнере разработки и на Linux-раннере GitHub
Actions, где нет Microsoft.NET.Sdk.WindowsDesktop. Цена — окна чуть многословнее в коде.
Значки кнопок тоже рисуются в коде: нет файлов картинок и лицензий на наборы иконок.

## 8. Технические решения

Решения D-001…D-006 — в [discovery/DISCOVERY-LOG.md §6](discovery/DISCOVERY-LOG.md). Дополнения при реализации Р0:

| ID | Решение | Почему |
|---|---|---|
| D-007 | WPF без XAML, значки в коде | сборка на любой ОС, нет зависимостей от картинок (§7) |
| D-008 | UI в сборке надстройки, не отдельной DLL | UI всё равно зависит от Revit API (§1) |
| D-009 | Установщик ставит сборки для всех трёх годов отдела, не ища установленный Revit | поиск Revit по реестру или папке ошибается при нестандартной установке; лишняя папка Addins\<год> безвредна, а надстройка заработает сразу после установки этого Revit |
| D-010 | Правила-категории — имена BuiltInCategory, а не русские названия | не зависят от языка Revit (REQ-UI-002) |
| D-011 | Действия GitHub Actions зафиксированы точными тегами релизов | «latest» запрещён; переход на SHA коммитов — отдельной задачей |
| D-012 | Объединение систем: неоднозначную копию (REQ-MEP-005) подтверждает отметка пользователя в окне, а не параметр-свидетель | в моделях отдела LSR_Имя системы заполняется от типа и ничего не различает (v1.2 такой свидетель отключает); человек видит копию в модели через «Показать в модели». По умолчанию такие строки не отмечены |
| D-013 | «Применить» доступна только после успешного пробного прогона с теми же отметками; перед каждым действием анализ строится заново | окно немодальное, модель могла измениться; порядок dry → trial → run из v1.2 закреплён в интерфейсе |
| D-014 | Объединение: всё или ничего на весь запуск, а не на группу | частично объединённая модель хуже исходной; проблемную строку снимают и повторяют |
| D-015 | Объединение: одна транзакция на группу «основная ← копии» (все копии удаляются и добавляются разом), модель систем ленивая — без обхода всех семейств | на КрМа3 пробный прогон по копии на транзакцию не дождались: каждая фиксация пересчитывает основную систему на 4000+ элементов и запускает IUpdater других надстроек. Проверка после группы ловит то же, что ловила после копии, но откатывает группу целиком |
| D-016 | Прогресс и отмена — немодальное окно в главном потоке: при каждом шаге и в событии Revit `ProgressChanged` окно перерисовывается (DispatcherFrame, не чаще 150 мс); главное окно Revit на это время отключено (`EnableWindow`); отмена — исключение на ближайшем шаге или `ProgressChangedEventArgs.Cancel()` во внутренней операции Revit, далее обычный откат TransactionGroup | API Revit однопоточный, фоновый поток к модели нельзя. Риск: прокачка сообщений во время внутренней операции Revit — повторный вход в Revit исключён отключённым окном и ExternalEvent (запросы ждут конца операции). Если в Revit всплывут сбои при перерисовке — прокачку в `ProgressChanged` отключаем, останется отмена между шагами |
| D-017 | Упавшее при фиксации обновление другой надстройки из списка в `SystemMergeExecutor` (сейчас только Citrus [BIM]) отключается: в `FailureCollector` отказ `DUMisbehavingUpdater` разрешается решением Revit по умолчанию (`ResolveFailure`) → `ProceedWithCommit`, только если других ошибок нет, имя апдейтера в тексте однозначно указывает на надстройку из списка, решение разрешено и ещё не пробовалось | Citrus «MEPUpdater» срывал фиксацию «К1.1» и «К1н» на КрМа3 при любой настройке расчёта; выбор пользователя 2026-10-09 (варианты: выключать самому / плагин отключает / не объединять). `UpdaterRegistry.DisableUpdater` недоступен: `UpdaterInfo` не даёт `UpdaterId`. Цена: до перезапуска Revit надстройка не обновляет свои данные, и откат пробного прогона этого не возвращает — пишем об этом в результате. Список расширять только решением пользователя |
| D-018 | Вызов Revit, который может не вернуться (MEPSystem.Add), окружён меткой-файлом `%LocalAppData%\VKTools\running-<pid>.txt`; брошенная метка при запуске уходит в `hangs.txt`, окно объединения предупреждает перед повторным запуском тех же копий | Прервать вызов внутри Revit нельзя (API однопоточный, Revit не шлёт ProgressChanged во время Add); остаётся не наступать дважды на одно и то же. Метка по pid, потому что в одном профиле бывают одновременно Revit 2021 и 2022 |
| D-019 | Участок копии без системы после фиксации, ни с чем не соединённый (нет соседей вне участка), не блокирует объединение: предупреждение в отчёте с «Показать в модели», итоговая проверка его не считает «потерявшим систему». Участок без системы, соединённый с чем-либо, — ошибка и откат, как раньше. Переключатель `LeaveIsolatedPiecesWithoutSystem` | Рекомендованный вариант карточки 2026-10-09 («К1.1» на КрМа3); если пользователь выберет «сначала чинить» — переключатель в false. Такой участок и до запуска оторван от сети; держать из-за него всю группу — значит не объединить 360 эл. из-за 12. Соединённый участок без системы — признак того, что Revit разорвал сеть не там, это нельзя пропускать |
| D-020 | Стык сети копии с сетью другой системы (строка отчёта с `CheckFinding.JunctionWith`) рвётся по кнопке «Разорвать стык…»: `Connector.DisconnectFrom` только между выбранной парой, одна транзакция на все пары, проверка «не соединены» и «не сдвинулись» после Regenerate, иначе откат. Автоматически плагин стыки не рвёт | Решение пользователя (карточка 2026-10-09, «Да, кнопкой»). Revit держит одну систему на связную сеть: напорная К4.2н, врезанная фланцем в К4.1, отдельной системой не удержится. Кнопка не трогает геометрию и длины. Рвать или нет — решает проектировщик по строке отчёта |
| D-021 | Перед объединением — поиск колец в сети основной с копиями (`Core.Mep.NetworkLoops`: кольцо → соединение с наибольшей высотой → мысленно убрать → искать дальше). Есть кольца — Revit не запускается, весь прогон «не запускалось», по строке отчёта на кольцо с предлагаемым местом разрыва (`JunctionWith`, кнопка D-020) | КрМа3, 2026-10-09: MEPSystem.Add зависал только на «К1» (2 кольца) — дважды, на разных терминалах, 15+ мин, Revit закрывали принудительно; около 30 прогонов без колец — доли секунды. Связь выведена по наблюдению, не по документации Revit. Разрыв соединения внутри кольца не делит сеть, система остаётся одной |
| D-021 (отменено в 0.3.12) | Блокировка по кольцам снята, кольца — только строка лога | Пользователь разъединил оба кольца «К1 2», MEPSystem.Add в «К1» всё равно не вернулся; «К1» ← «К1 1» висла и без колец. Связь «кольца → зависание» была выведена по совпадению |

## 9. Поток «Объединить системы» (Р1, с 0.3.0)

```
MergeSystemsCommand  [ReadOnly] — только анализ, открывает окно
   │
   ▼
SystemMergePlanner.Build(doc, progress, timings, [ключи])   модель не меняется; окно прогресса, «Отменить»
   ├─ PipingModel: все PipingSystem; элементы, сеть и терминалы системы — по запросу, с кэшем
   ├─ Core MergeGrouping.BuildGroups: группы «основная ← копии» по именам, типу, классификации
   │     копии без основной, основная в двух экземплярах, почти совпадения → «не объединяется»
   └─ проверки копии по модели: терминалы, базовое оборудование, классификация коннекторов,
        связи с системами другой группы, группы, варианты, совместная работа
   ▼
MergeSystemsWindow (немодальное) — отметки, «Показать в модели», «Отчёт…»
   │  «Пробный прогон» / «Применить» / «Обновить» → ExternalEvent → MergeSystemsHandler
   ▼
MergeSystemsHandler: анализ заново только отмеченных групп → MergeDiagnostics в лог → SystemMergeExecutor
   TransactionGroup «VK Tools: объединение систем»
     на каждую группу одна Transaction + FailureCollector (предупреждения в отчёт, ошибка → откат;
       упавший апдейтер Citrus [BIM] без других ошибок → отключить до перезапуска Revit и фиксировать, D-017):
       Delete(все системы-копии группы) → MEPSystem.Add(коннекторы терминалов) по каждой копии [повтор после Regenerate]
       → Regenerate → проверка: терминалы в основной, геометрия на месте → Commit
       → проверка сети после фиксации: все элементы копий в основной, нет новых систем (иначе — куда ушли; откат всего)
     итоговая проверка по каждой основной и по всем элементам ("!!!" → откат)
   Trial / отмена / ошибка → RollBack; Apply → Assimilate (одна запись отмены)
   время этапов (OperationTimings) → лог и «Итоговая проверка»
   ▼
полный анализ заново → окно (объединённые строки остаются с результатом), отчёт
```
